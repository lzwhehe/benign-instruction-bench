\section{Methodology}
\label{sec:method}

\subsection{Evaluation sets}

\paragraph{General benign text}
We sampled \NGeneral chunks of 80--220 words, about 2{,}500 each from GitHub READMEs\footnote{\url{https://huggingface.co/datasets/h1alexbel/github-readmes}}, business emails (AESLC~\cite{aeslc}), and educational web pages (FineWeb-Edu~\cite{fineweb}). Every chunk is benign.

\paragraph{Clean agent tool outputs (AD-Clean)}
AgentDojo v1.2 ships, for every user task, the sequence of tool calls that solves it~\cite{agentdojo}. We executed these calls in the default environment, without any injection and without an LLM, and recorded each tool output exactly as AgentDojo formats it for the agent. This yielded \NCleanOutputs outputs from \NCleanTasks tasks in four suites (workspace, travel, banking, and slack). Every output is benign by construction and belongs to a task, so false positives translate into blocked tasks.

\paragraph{Matched agent tool outputs (AD-Matched and AD-Shift)}
We placed one of AgentDojo's built-in attacks into every injection point of a task's environment and replayed the same ground-truth calls. An output was labeled \emph{injected} if it differed from the output of the same call in the clean environment, and \emph{benign} otherwise. Substring matching is not sufficient for this purpose, because AgentDojo serializes outputs as YAML, which re-wraps multi-line injected text (\ref{app:labels}). AD-Matched uses three attack templates (\texttt{important\_instructions}, \texttt{ignore\_previous}, and \texttt{direct}; \NADBenign benign and \NADInj injected outputs). AD-Shift uses five others (\texttt{tool\_knowledge}, \texttt{injecagent}, \texttt{system\_message}, and two variants of \texttt{important\_instructions}; \NADSBenign benign and \NADSInj injected outputs). All AgentDojo injection goals are actions.

\paragraph{A second agent benchmark ($\tau$-bench)}
$\tau$-bench~\cite{taubench} simulates customer-service agents for a retailer and an airline over JSON databases and ships ground-truth tool calls for each task. Its authors, domains, tools, and output format (JSON) all differ from AgentDojo's. Replaying the ground-truth calls of all \NTBTasks retail and airline tasks without an LLM gave \NTBBenign tool outputs that are benign by construction (TB-Clean). $\tau$-bench has no injection points, so we added one where a third party plausibly controls text: the catalog name of a product, which a marketplace seller writes. For each retail task that looks up a product, we appended an attack instruction from InjecAgent~\cite{injecagent} (MIT license; its base and enhanced settings, eight attacks per task, all 62 attacks used) to the names of the products the task looks up, replayed the same calls, and labeled by differential replay. This yielded \NTBInj injected outputs, which we evaluated against TB-Clean as negatives (TB-Matched). InjecAgent's attacks share neither authors nor templates with AgentDojo or BIPIA.

\paragraph{BIPIA}
BIPIA~\cite{bipia} provides clean external content for the three tasks we used (email question answering, table question answering, and code repair with a Stack Overflow answer) and attack strings in three text groups and two code groups. Each clean context is a benign sample; we inserted four randomly drawn attack strings at the start, middle, or end, following BIPIA's insertion rules, to obtain injected samples. BIPIA splits its attack strings into a training and a test half. Our main results use only test-half attacks (\NBIBenign benign and \NBIInj injected samples), and Section~\ref{sec:rq3} uses both halves.

\subsection{Training-data audit}
Two detectors publish enough to audit. PIGuard's authors release its training split. We normalized whitespace and case and searched it for (i) the first 80 characters of every BIPIA attack string and (ii) the first 120 characters of every clean BIPIA context. Horizon-Labs releases the script that assembles its training set from public datasets; we downloaded the five sources that contain agent or tool-output injections and searched them for BIPIA's attack strings and for markers of AgentDojo's attack templates (for example, the opening sentence of \texttt{important\_instructions}). We also searched both for InjecAgent's 62 attack instructions. Both searches find only verbatim copies and are therefore lower bounds on overlap. The other detectors name their sources at most, so for them we report what their model cards state.

\subsection{Metrics and thresholds}
We report the false-positive rate (FPR) and true-positive rate (TPR) at each detector's default threshold of 0.5, the area under the ROC curve (AUROC), and the TPR at 1\% FPR. A deployment sees benign outputs far more often than injected ones, so the low-FPR operating point is the one that matters, as in membership inference~\cite{lira} and deployable injection detection~\cite{promptshield}. For AD-Clean and TB-Clean we also report the share of tasks with at least one flagged output. Unless stated otherwise, the 1\%-FPR threshold is chosen on the same benign set that is evaluated, which favors the detectors; a deployment would have to choose it in advance.

Section~\ref{sec:robust} therefore repeats the AgentDojo evaluation with thresholds set on other data. A same-set variant takes the threshold that flags at most 1\% of AD-Clean outputs and applies it to AD-Matched; it is not held out, because every benign AD-Matched output also occurs verbatim in AD-Clean (\AdMatchedBenignInClean): an injection changes only the outputs that read an injection point. The held-out protocol, our main result, leaves out a whole suite: the threshold is set on the AD-Clean outputs of three AgentDojo suites at a budget of 1\% or 2\%, and detection and false positives are measured on the fourth suite's AD-Matched injections and AD-Clean outputs, pooled over the four folds. With 215 to 306 calibration outputs per fold, a 1\% budget allows two or three benign outputs above the threshold, so we report the false-positive rate realized on the held-out suite.

\subsection{Statistical analysis}
Intervals are 95\% percentile bootstrap intervals over \NBoot resamples, stratified by label (by task for task-level rates). We measured agreement between two benchmarks' rankings of the \NDetectors standalone detectors with Kendall's $\tau$ and quantified two sources of uncertainty. Sampling of test items was captured by a stratified bootstrap (\NBoot resamples of every evaluation set, shared by all detectors). Chance agreement among only \NDetectors detectors was assessed by a permutation test that shuffles one benchmark's scores across detectors (10{,}000 permutations). A narrow bootstrap interval indicates a stable ranking of these detectors; only a small permutation $p$-value indicates an association unlikely without a real relationship. Neither test can show that two rankings are unrelated, so for non-significant correlations we rely on concrete reversals.
